## 1. Meaning and permission

Correct keeps the memory id and scope, saves revision n+1, and supersedes n. Require the expected current revision. Replace the full checked value, preserving kind/pin/expiry unless explicitly changed. Preferences remain personal. Preserve checked source links and dependencies. The old revision immediately stops being readable through memory APIs or usable as context. Destroy its key during cleanup: cryptographic erasure is complete only when cleanup completes. There is no old-text history or rollback. Even pin/unpin uses a checked correction for #98.

Forget records a permanent tombstone, hides the whole fact immediately, and schedules erasure of every revision and dependent copy. Nothing called Restore or Undo forget exists. Undo store is a fresh forget command against the stored revision; if it changed, review the latest revision.

| Scope | Human correct and forget | Agent correct and forget |
| --- | --- | --- |
| Person | Active member who owns it, with current scope read and write rights. | That requester through their bound assistant, with separate recorded requester and assistant read/write grants. |
| Assistant notes | Current personal owner or owner-group member in the assistant audience; active assistant, `actsFor`, explicit notes read and write grants. | Refuse shared mutations until trusted shared-only execution lands; then require that audience and requester ∩ assistant operation grants. |
| Group | Active member recorded in that group and allowed by OpenFGA `team#member`; may change any group fact, without an approval queue. | Refuse for current private execution. Later shared-only execution must belong to the assistant's owner group and hold both operation grants. |

Keep #319's mechanical restriction on shared agent writes. A scope id, source link or model claim cannot turn a private thread into shared-only execution. Do not relax it just for forget. For personal assistant notes, retain the same agent restriction until explicitly qualified. Humans can use the shared APIs meanwhile. All corrections need current read AND write permission; write-only notes access cannot edit or forget an unreadable fact. A known tombstone can return safe status to an authorised caller without decrypting old text or requiring its key.

Decide from current member/team/assistant/grant events plus OpenFGA checks and applied receipts. Use the existing `memory_read`/`memory_write` resources, with each tool's own published policy. Read permission alone is insufficient. Refuse revoked, unapplied, foreign-silo or inactive bindings; IAM outages are unavailable. Never obtain authority from model text or remembered instructions.

Read bounded fact/source/command history before the two-second `authorityFence`. Watch only small member, assistant, relevant team, grant and admission payer streams; retain the existing MCP policy check. Never add memory-content or whole conversation streams to that access check. Use the scope stream's expected sequence for content races. Recheck immediately before the single append. Reads check access once, without a fence. Use bounded turn summaries for lifecycle checks. Messages, uploads and unrelated turns cannot deny a reader or close their memory panel.

An Owner/Admin can configure recorded grants and inspect authorised payload-free operations. They gain no right to read, correct, forget or export another person's memory by being an admin. A group-member admin acts through membership. Retrying an existing cleanup job cannot choose a new deletion target. Infrastructure operators can access disks/keys; application permissions do not protect against the host owner or recall a disclosure already delivered to another service.

## 2. Where text or keys can survive, and how to close each route

Key destruction is the erase of encrypted payloads. A tombstone is the immediate use prohibition. Deleting a search row alone is insufficient; deleting a key alone leaves plaintext search behind. The event log keeps encrypted written/corrected values, opaque key references, source/dependency ids, revisions, actors and times. Forget and cleanup evidence contain no text or ciphertext. Do not add plaintext reasons, snippets, text hashes or raw request/response bodies to audit history.

| Place | Required closure |
| --- | --- |
| Old revisions and revision keys | Enumerate from scope events, not the current row. Correct destroys superseded keys; forget destroys all committed revisions plus safely reconciled candidate keys. Never re-provision a committed destroyed revision. Remove `-pending` hard links too. |
| Derived facts, summaries and duplicates | Preserve dependencies for ALL revisions. Walk them transitively in TypeScript. Forgetting any source invalidates every dependent fact, even if its current revision removed the link. Erase every revision of those dependent facts. |
| Projection/search text and vectors | Tombstone application removes plaintext and vectors for the root and dependent facts in one projection transaction. Keep only safe status/history metadata. Filter list, detail, search, cursors and initial context by the same event-derived validity rule. |
| Projection lag and reads in flight | Require catch-up to the relevant scope position and generation. Check returned references against current content before delivery; stale content is retried or unavailable. A read that completed before forget cannot be recalled; its result cannot authorise a later dispatch/write. |
| Rebuild/replay, including cleanup not yet finished | Fold metadata through a fixed event position first. Determine hidden ids, invalid dependencies and superseded revisions before decrypting anything. Never decrypt or insert their old text, even into intermediate rebuilt tables. Keep readers stopped until catch-up succeeds. |
| Missing keys and deletion markers | An empty marker is destroyed. Missing/damaged files and an absent directory are custody errors, not proof of erasure. Markers survive restart/restore; replay never creates keys. Refuse service on incomplete custody recovery. |
| Server, gateway and browser caches | No plaintext persistence, response cache, localStorage, IndexedDB or service-worker cache; use `no-store`. Drop affected drafts, previews and result buffers on content invalidation; drop all protected state on access/requester change. Ignore late replies using request/content generations. |
| Open recall proofs and initial-context references | Sign ids/revisions only. Verify current validity at use, independently of the signature. Reject forgotten, superseded, expired, missing-key or invalid-dependent references. Bind proofs to the live thread and content generation. |
| Delayed remember/correct/dream writes | Validate all dependencies and expected revisions from the same scope snapshot. One conditional scope append means either the write preceded forget and is erased, or it conflicts after forget. Never retry by dropping dependencies or changing ids. |
| Context already sent and resumed turns | Stop affected execution, discard late generated output and replace its private session before another model/tool dispatch. Reconstruct from authorised transcript plus fresh live memory references. Never resume the old rollout or use a conversation-key copy of recall. |
| Private generated snippets and reports | Keep volatile, or encrypt with separately destroyable keys linked to ALL contributing memory references. Removing a source removes those payload keys too. Audit/tool evidence stores references, not permanent recall bodies. |
| Computer files, logs, dumps and provider caches | Keep memory-loaded execution behind #96's qualified RAM/tmpfs/no-write boundary. Disable swap/core dumps and durable tool persistence. Do not enable native memory without the proof. Never promise removal of data already retained by an external provider. |
| Backups, WAL, snapshots and old key volumes | These can contain plaintext or old key bytes. Honour retention; on restore overlay the latest deletion markers and full retained tombstones before any reader/worker/turn resumes. A restore missing newer deletion evidence stays offline. File replacement does not shred free blocks or snapshots. |
| Independent chat messages and deliberate new statements | Forget does not erase these resources. Their access checks still apply. A new explicit human command with independent live sources may store new text under a new id; it must not automatically recreate the forgotten lineage. No semantic text blacklist is promised. |

Change `memory_dependencies` to retain revision-specific edges: its current primary key lacks the owner revision and current writes delete older edges. Rebuild historical edges from events. Compute the affected set using ids/revisions only, with a visited set; no model, SQL recursion business rule, cross-group copying or text matching. Expired/destroyed dependencies are unusable. Old unversioned events keep their explicit parser and quarantine; never guess ownership/lineage.

For correction, invalidate dependent facts that used the superseded revision, transitively. The replacement itself is excluded from that incoming dependency closure: `supersedes` records ordering, not an obligation to retain the old key. Keep its own checked outgoing dependencies. An editor cannot erase lineage merely by omitting it. Default to preserving prior dependencies and adding new ones; independent recreation requires a separate, explicit new fact.

The #319 proof accepts caller-selected subsets. That cannot establish complete deletability. Require trusted evidence of every memory reference loaded into that execution, using existing turn/tool evidence with text-free references. Conservatively carry all those dependencies into derived writes. If evidence is incomplete, exceeds the bound or spans prohibited scopes, refuse the write. A signed selective proof alone cannot bypass this. Native initial-context/recall accumulation and source-linked private outputs are #97 gates, not permissions inferred by #95.

## 3. Events, commands, statuses and cleanup

Keep `scope-<scopeId>` / `ev.scope.<scopeId>` and versioned identity/limits from #94: 4,096 UTF-8 text bytes, 8 sources, 32 dependencies, 16 KiB command/event size and safe-integer revisions. AES-256-GCM gets a fresh nonce; additional data binds silo, scope kind/owner, fact and revision. Prepare keys before append as custody work, never as a second business-state write. Fold all three change types into one current-state reader; the existing written-only command history and dependency checks must not skip a later correction or tombstone. Hidden identities are permanent: a later high revision or duplicate write cannot make them live. Reject cycles, self-dependencies and any new dependence on an invalid revision before append. Retain ordering references separately from payload dependencies. A target proof for correct is not a dependency on its own superseded revision. Mark transitive dependent invalidation from the root event; do not need one separate user command or tombstone append per dependent fact.

| Event | Proposed version-1 data and effect |
| --- | --- |
| `memory.corrected` | Full checked new value with ciphertext/keyId, expectedRevision n, revision n+1, `supersedes` fact/revision, typed sources/dependencies and bounded reason enum human/merge/contradiction/expiry. Publish replacement; hide superseded/dependent content; request cleanup. |
| `memory.forgotten` | Scope identity, memoryId, expectedRevision n and tombstone revision n+1. No text, ciphertext or new key. Permanently hide the id and dependent closure; request cleanup. |
| `memory.cleanup_recorded` (new) | Scope identity, initiating changeId, root memoryId, status completed/unavailable, observation time and optional safe failure code. No payload/key bytes. Record physical cleanup evidence for that specific change, without changing fact content. |

Keep legacy correct/forget schemas explicitly for replay; quarantine values without trustworthy identity/revision. Add the new schema, registry entry, examples, catalogue projection/reaction rows and docs together. The catalogue already says tombstone first: preserve that order and add correction cleanup. Cleanup evidence triggers no new cleanup job. Do not enable reserved promotion.

`correct(commandId, scopeId, memoryId, expectedRevision, fullReplacement)` and `forget(commandId, scopeId, memoryId, expectedRevision)` share human/agent validation internally. Command identity includes silo, principal kind/requester, scope and commandId. Consume a command once across operations; changed target, operation, revision or live replacement is conflict. One attempt performs one conditional append; no automatic second append. A lost reply stays unknown and is reconciled through the original command. A stale edit/forget is 409, then refresh and review; never overwrite. A consumed erased command returns safe current status without key provision or text comparison. Do not persist a text fingerprint to recover that comparison.

Protect correction preparation with a short fact-specific lock and its recoverable custody reservation. Existing command-specific locks alone do not protect a shared revision key slot. Two corrections of r3 both target the deterministic r4 key. A losing attempt MUST NOT destroy the accepted attempt's key. If r4 was never committed, retain at most that next-revision candidate key for a later checked correction; do not permanently mark r4 destroyed and then try to reuse it. Keep unknown reservations until event history proves the outcome or makes the delayed append impossible. Reconcile before admitting another candidate for that slot. On forget, the scope append invalidates older candidates; cleanup also erases their keys and journal remnants. Retained candidate keys are custody records, hold no fact text and never authorise publication.

| Public state | Exact meaning |
| --- | --- |
| hidden | Forget append proved; root/dependent text cannot be used. Do not wait for workers to acknowledge this prohibition. |
| cleanup-pending | Same hidden state; key/text cleanup is unfinished or completion evidence is not caught up. Corrections return this separately from their accepted new revision. |
| forgotten | Completion event proved after all affected key markers and projection/search removal were verified; include its real time. No claim that backups or previous disclosures were erased. |
| unavailable | Before append: operation/service could not be established, with unknown kept distinct. After append: `hidden: true`, cleanup unavailable, never a restored fact. Missing-key live facts are unavailable, not automatically forgotten. |

Receipts return operation, changeId, memoryId, accepted revision, scope/audience, acceptedAt, content status and cleanup status; no raw fact text. Status keeps the original accepted result and the fact's present state separate. An old store receipt cannot offer Undo against a newer revision without review. No saved receipt is reconstructed by decrypting its erased payload.

Register `cleanup-memory` with the existing handler runtime for corrected/forgotten events. Read current silo/scope events, recompute obligations from all historical revisions and edges, and skip keys outside those obligations. A later correction/forget cannot be undone by an old cleanup job. Use trusted silo cleanup authority; requester removal does not cancel an accepted erasure. Do not recheck a user's now-revoked write grant to decide whether to keep their old key.

For each obligation, idempotently install the durable empty marker and remove temporary copies. Require projection catch-up and absence of affected plaintext/vectors before completion. The reaction never writes the runner's memory tables; the projection performs those changes from events, and progress commands each do their own single append. Record completed only after verification. If progress append fails, retry verification and append safely; keys stay erased. Status defaults to pending until completion is recorded, even if physical cleanup already finished. Fold progress by initiating changeId, with completed terminal for that obligation. An old correction's progress cannot overwrite a later forget status or make its replacement disappear. Delete only revision identities proven obsolete by events; never the current live replacement.

Reuse five runtime retries, exponential backoff from one second and a 60-second attempt timeout. Process large closures in bounded chunks; after restart recompute and skip destroyed keys. If deletion fails, fail the job, retain the tombstone, and retry; no receipt of success. On retry exhaustion, record unavailable once, retain the failed original job and alert with safe ids/codes. The existing operator retry acts on that original job after repair; success records completed. Later jobs may be held by FIFO failure; this cannot restore hidden facts or deny unrelated reads. Duplicate failure/completion reports converge by initiating change and episode, without text. After loss of job tables, rebuild pending obligations from events and markers before resuming; projection replay itself runs no reaction, key provision/deletion or model calls.

## 4. Governed tools inside a turn

Extend existing stateless MCP 2026-07-28 parsing, policies and `/mcp/memory/server`; do not add a bypass endpoint. `correct` takes the command fields, replacement and proof of the target plus checked dependencies. `forget` takes command fields and a proof of the target expected revision. Proofs contain no text. Add detail recall by memory id if needed to obtain the exact target. Forget needs scope read/write rights and a checked metadata revision, not decryptable text. An authorised unavailable detail may supply a metadata-only signed target proof for forget; it cannot supply usable recall dependencies or allow correction of unavailable content. Human HTTP actions need current identity/access, not a model turn or synthetic signed headers.

Both tools use reviewed zero-cost Allow policies. Ask is refused as a configuration mismatch; Block denies. Do not open a group approval queue or silently treat Ask as Allow. The human Forget review is explicit destructive intent, not a governed tool approval. Current private agent calls remain person-only. Record tool selection/grants through existing catalogue commands.

Extend the signed `x-memory-context` operation enum. Verify issuer/audience, signature, silo, requester, assistant, computer generation, conversation, turn/thread, content class, operation, scope, method/name/version, body digest, callId/requestId and original expiry of at most two seconds. Recheck current recorded grants AND OpenFGA read/write rights at the backend and final append; a valid signature cannot survive revocation. Strip client identity/scope/secret headers. Bind recall proofs to the same identity plus content generation, verify their current revisions and complete lineage, and enforce the original append deadline. Ended/replaced/forged contexts deny.

Do not confuse authority `contextPosition` with content freshness. #95 supplies a shared checked reference validator and text-free invalidation information keyed by affected fact/revision.
\#97 records loaded references, checks them before every dispatch/report release, and replaces
affected private sessions. Stop/rebuild on correction, forget or revoke before further work; discard late output from the old generation. Lose the reference evidence: refuse and rebuild. An unrelated scope change need not rebuild a thread. Access changes clear viewers; memory changes refresh their data. Resume cannot inherit another requester's context.

Advertise each new tool only in the PR that lands its working handler, policy and refusal tests. Filter `tools/list` by current policy; discovery advertises no unimplemented operations or private facts. Native forwarding, shared-only execution and RAM/disk qualification remain #96/#97 gates.

## 7. Open questions and recommended defaults

- Does “old one unreadable” require immediate key destruction? Default: immediate API/context prohibition, followed by verified physical cleanup; show pending/unavailable honestly.
- How strict is derived lineage? Default: all trusted loaded references, historical edges and conservative transitive deletion. Refuse incomplete or cross-scope evidence; no model judgement.
- Can a human remove dependency links during correction? Default no. Use a new explicit fact with independent live sources; never auto-copy the forgotten payload into a new lineage.
- What handles failed candidate correction keys? Default: one recoverable next-revision custody slot per fact; retain it until reuse or forget. Do not delete a concurrent accepted key or change the existing deterministic key identity just to simplify error handling.
- Should cleanup completion be an event? Default yes, `memory.cleanup_recorded`; queue receipts remain operational evidence, not sole durable truth after replay. No event per retry.
- When may shared agent mutations land? Default: keep #319's person-only rule until a separate qualified shared-only execution outcome exists. Human group changes remain approval-free.
- What about already delivered context and backup erasure? Default: stop/rebuild future work, no retraction promise; retain the explicit chat/backups exception and enforce safe restore.
- Which budgets and completion gates apply? Default: the serial ≤600-line outcomes above, fresh-install #95 proof, and explicit #96/#97 native-runtime gates. Designs are not PASS evidence.
